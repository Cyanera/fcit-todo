# مهام FCIT

بوت يستمع لقروب واتساب بشكل مستمر، يستخرج المهام الموجّهة لك تحديدًا، ويعرضها في
لوحة عربية مع تنبيه فوري للعاجل منها.

يشتغل بوضعين: **قواعد** بصفر تكلفة، أو **تصنيف ذكي عبر Claude** أدق وأشمل.

الهدف: تتوقف عن متابعة القروب لحظة بلحظة، وتفتح اللوحة لما تكون فاضي.

---

## كيف يشتغل

```
قروب الواتساب
   │  Baileys — جهاز مرتبط، يستمع 24/7
   ▼
تجميع الرسائل في دفعات (كل 60 ثانية أو 25 رسالة)
   │  دفعة واحدة بدل استدعاء لكل رسالة = تكلفة أقل وسياق أوسع
   ▼
الاستخراج — يحدد لكل رسالة: هل هي مهمة عليك؟
   + العنوان + من طلبها + الموعد + الأولوية + نسبة الثقة
   (عبر Claude في الوضع الذكي، أو بقواعد عربية بصفر تكلفة)
   ▼
SQLite ──► لوحة ويب على المتصفح
        └► تنبيه فوري في "رسالة لنفسي" للمهام العاجلة
        └► ملخص يومي الصباح
```

كل مهمة تحتفظ بنص الرسالة الأصلية واسم مرسلها ووقت إرسالها، فتقدر ترجع
للسياق قبل ما تنفّذ.

> واتساب لا يوفّر رابطًا يفتح رسالة بعينها — روابطه تفتح محادثة مع شخص أو
> دعوة قروب فقط — فلا يمكن جعل الضغط على الرسالة ينقلك إليها داخل التطبيق.

## التشغيل

### 1. المتطلبات

- Node.js 20 أو أحدث
- رقم واتساب
- مفتاح Claude — **اختياري**، للوضع الذكي فقط.
  من [console.anthropic.com](https://console.anthropic.com/settings/keys) (يحتاج رصيد مدفوع،
  أقله ٥$). بدونه يشتغل البوت بوضع القواعد.

### وضع صندوق الوارد — الموصى به لقروبات العمل الرسمية

بدل ربط البوت بقروبات العمل، اجعل القروب المراقَب **صندوق وارد خاصًا بك**
وحوِّل إليه يدويًا ما يخصك من رسائل. عندها:

- البوت **لا يقرأ أي قروب رسمي إطلاقًا** — لا تخزين لرسائل زملائك ولا تعرّض
  لخصوصيتهم. وهذا يحسم أكبر تحفّظ على المشروع.
- **كل رسالة تصل = مهمة** بحكم أنك حوّلتها، فيسقط أصعب جزء وأكثره خطأً:
  تخمين «هل هذه مهمة؟». لا مهمة فائتة ولا إيجابية كاذبة.
- العمل يصير استخلاصًا خالصًا: ما الإجراء المطلوب، وما روابطه، وما موعده.

```bash
INBOX_MODE=true
GROUP_JIDS=<معرّف قروب الصندوق>
```

الاستثناء الوحيد: رسالة فارغة أو إيموجي وحده. الروابط تُستخرج إلى وصف المهمة
قابلةً للنقر، والموعد إلى حقله، والعنوان يحمل المطلوب وحده.

### وضعان للتشغيل

| | **قواعد** (`MODE=rules`) | **ذكي** (`MODE=claude`) |
|---|---|---|
| التكلفة | صفر | رصيد API مدفوع |
| يقرأ | كل رسائل القروب | كل رسائل القروب |
| يلتقط | أي رسالة فيها إشارة طلب — جماعية كانت أو باسمك | نفسه، مع فهم السياق |
| يستبعد | الموجّه لزميل بالاسم، والتحيات والشكر | نفسه، بدقة أعلى |
| العنوان | المطلوب وحده — يختار فقرة الطلب من التعميم الطويل | معاد صياغته بصيغة أمر |
| اللغة | عربي فصيح وعاميّة خليجية وإنجليزي | الثلاثة، مع فهم أعمق |
| يفوته | الطلب الضمني بلا صيغة طلب واضحة | قليل |

`MODE=auto` (الافتراضي) يختار الذكي لو وجد مفتاحًا صالحًا، وإلا القواعد. يعني تقدر
تبدأ اليوم بصفر تكلفة، وتضيف المفتاح لاحقًا فينتقل وحده بدون أي تغيير ثانٍ.

**المهام الجماعية هي الغالب** في قروبات العمل («لازم نرفع الدرجات قبل الخميس»)،
لذلك الوضعان يلتقطانها بلا اشتراط نداء باسمك. `MY_NAMES` يرفع الثقة فقط،
و`OTHER_NAMES` يستبعد ما هو موجّه لزملائك.

### الاختبارات

```bash
npm test
```

١١ اختبارًا تغطي: الالتقاط الجماعي، استبعاد ما هو لزميل، الضجيج، التباس الأسماء،
تمييز الماضي من الأمر، وتحويل المواعيد. **شغّلها بعد أي تعديل على قوائم الكلمات
في `src/rules.js`** — أضف حالتك الجديدة كاختبار أولًا.

**حد وضع القواعد:** لا يفهم الزمن ولا السياق. يستبعد صيغ الماضي («أرسلت التعميم»
خبر لا طلب)، لكن ستمرّ بعض الإيجابيات الكاذبة — احذفها بضغطة من اللوحة.

### 2. التثبيت

```bash
npm install
cp .env.example .env
```

افتح `.env` واضبط:

| المتغير | الشرح |
|---|---|
| `MODE` | `auto` / `rules` / `claude` — انظر الجدول فوق |
| `ANTHROPIC_API_KEY` | مفتاحك من الكونسول. اتركه كما هو لتشغيل وضع القواعد |
| `MY_NAMES` | الصيغ التي ينادونك بها — ترفع ثقة المهام الموجّهة لك |
| `OTHER_NAMES` | أسماء زملائك — أي طلب موجّه لهم يُستبعد من مهامك |
| `INCLUDE_OWN_MESSAGES` | `true` لالتقاط رسائلك أنت — مفيد للتجربة وحدك |
| `GROUP_JIDS` | معرّف القروب (تجيبه في الخطوة 4) |
| `CLAUDE_MODEL` | `claude-opus-5` افتراضيًا. للقروبات كثيرة الحركة جرّب `claude-sonnet-5` |
| `MIN_CONFIDENCE` | الحد الأدنى لتسجيل المهمة. ارفعه لو طلعت مهام زائدة |

> `npm start` يطبع لك عند الإقلاع أي وضع يشتغل فيه، واللوحة تعرضه في الأسفل.

### إعادة استخلاص المهام من رسائل محفوظة

```bash
npm run reprocess        # آخر 48 ساعة
npm run reprocess 12     # آخر 12 ساعة
```

الرسائل تُحفظ كلها، لكن الاستخلاص يجري مرة واحدة لكل رسالة. فإذا غيّرت
الوضع أو حسّنت القوائم في `src/rules.js`، تبقى المهام القديمة على نتيجتها
الأولى. هذا الأمر يعيد الاستخلاص الحالي عليها.

لا يتصل بواتساب — يقرأ قاعدة البيانات فقط، فيمكن تشغيله والبوت يعمل. ومنع
التكرار يحمي من ازدواج المهام.

### 3. ربط واتساب

```bash
npm run login
```

يطلع رمز QR في الطرفية. من جوالك: **واتساب ← الإعدادات ← الأجهزة المرتبطة ← ربط جهاز**.
الجلسة تُحفظ في `data/wa-auth` فما راح تحتاج تعيدها.

### 4. معرفة معرّف القروب

```bash
npm run groups
```

يطبع قروباتك مع معرّف كل واحد. انسخ سطر `GROUP_JIDS=` للقروب المطلوب وحطه في `.env`.

**أكثر من قروب؟** افصل المعرّفات بفاصلة:

```
GROUP_JIDS=120363411871315380@g.us,966596547883-1508011168@g.us
```

اللوحة تعرض عندها شرائح تصفية بعدد المهام في كل قروب، وكل مهمة تحمل اسم قروبها.
الدفعات تُعالَج لكل قروب على حدة، فالسياق وحساب التكرار يبقيان داخل القروب نفسه.

> لو تركت `GROUP_JIDS` فاضي راح يقرأ **كل** قروباتك — مكلف وغير دقيق. حدّد قروباتك.

### 5. التشغيل

```bash
npm start
```

اللوحة على `http://localhost:3777`.

## التشغيل الدائم على الماك

```bash
npm run service:install
```

يولّد إعداد `launchd` من مسارَي node والمشروع الفعليين، ويشغّل البوت في الخلفية
مع كل إقلاع للماك — فلا تحتاج طرفية مفتوحة.

| الأمر | الوظيفة |
|---|---|
| `npm run service:install` | التثبيت والتشغيل |
| `npm run service:status` | هل يعمل؟ |
| `npm run service:logs` | آخر السجل |
| `npm run service:restart` | إعادة التشغيل بعد تعديل الشيفرة |
| `npm run service:uninstall` | الإلغاء |

السجل في `data/run.log` داخل المشروع لا في `/tmp` — قد يحمل نصوص رسائلك،
و`/tmp` يقرؤه أي مستخدم على الجهاز.

> **بعد ترقية node عبر nvm** أعد `npm run service:install`: مسار node يحمل رقم
> الإصدار، فيتغيّر مع الترقية ويتوقف الإقلاع.

> **بعد تعديل الشيفرة** شغّل `npm run service:restart` — Node يحمّل الوحدات مرة
> واحدة، فالتعديل لا يسري قبل إعادة التشغيل.

> **انتبه:** الماك لما ينام ينقطع الاتصال بواتساب وتفوتك رسائل تلك الفترة،
> ويستأنف عند الاستيقاظ. لتغطية كاملة شغّل `caffeinate -s` أو انقل المشروع لسيرفر.

## ملاحظات مهمة

**حارس الإرسال — لا يستطيع الكتابة في أي قروب.** `src/guard.js` يُركَّب على
دالة الإرسال في المقبس نفسه فور إنشائه، ويرمي استثناءً لأي وجهة عدا محادثتك مع
نفسك: القروبات والأشخاص والقنوات والقوائم كلها ممنوعة. لأنه على المقبس لا على
شيفرة الاستدعاء، فهو يغطي أي شيفرة تُضاف مستقبلًا، ولا يمكن استبداله بعد تركيبه
(`writable: false`). تغطيه ٨ اختبارات في `test/guard.test.mjs`.

للتحقق بنفسك من أن الإرسال لا يحدث إلا لنفسك:

```bash
grep -rn "sendMessage" src/
```

**أعد التشغيل بعد تعديل الشيفرة.** Node يحمّل الوحدات مرة واحدة عند الإقلاع،
فأي تعديل بعده لا يسري حتى إعادة التشغيل — وهذا يُنتج عطلًا خفيًا: تظنّ الإصلاح
ساريًا وهو ليس كذلك. `src/freshness.js` يفحص بصمة ملفات المصدر كل دقيقة ويطبع
تحذيرًا واضحًا مرة واحدة عند اختلافها.

**نسخة واحدة فقط.** تشغيل نسختين بنفس اعتماد واتساب يجعلهما تتقاتلان بلا نهاية:
كل واحدة تزيح الأخرى (رمز `440`) فتعيد المُزاحة الاتصال فتزيح الأولى. `src/lock.js`
يحجز قفلًا في `data/bot.lock` ويرفض التشغيل إذا كانت نسخة أخرى حيّة، ويتجاوز
القفل اليتيم من عملية انتهت. وعند وصول `440` رغم ذلك، يخرج البوت بدل أن يعيد
الاتصال ويدخل الحلقة.

**الاتصال بالقروبات غير رسمي.** واجهة واتساب الرسمية (Cloud API) لا تدعم قراءة رسائل
القروبات إطلاقًا، لذلك يستخدم المشروع مكتبة `Baileys` التي تربط رقمك كجهاز مرتبط —
نفس آلية WhatsApp Web. هذا خارج شروط استخدام واتساب، والخطر الواقعي هو احتمال حظر
الرقم. البوت هنا **قارئ بشكل أساسي** ولا يرسل إلا لمحادثتك مع نفسك، وهذا يقلل
الخطر كثيرًا لكنه لا يلغيه. لا تستخدمه على رقم لا تتحمّل فقدانه.

**لا تُطبع مفاتيح التشفير.** مكتبة `libsignal` التي تعتمد عليها Baileys تطبع
كائن الجلسة كاملًا — ومعه `privKey` و`rootKey` نصًّا صريحًا — عند أحداث بروتوكول
روتينية. `src/quiet.js` يرشّح هذه الرسائل تحديدًا عند مستوى `console`، لأن
المكتبة لا تقبل logger مخصصًا لها وتعديل `node_modules` يضيع مع أول تثبيت.
بدون هذا الترشيح كانت المفاتيح تُكتب في ملف السجل عند التشغيل عبر launchd.

**خصوصية أعضاء القروب.** رسائل القروب تُخزّن محليًا في `data/tasks.db`، ونصوص الدفعات
تُرسل لـ Claude للتصنيف. المجلد كامل مستثنى من Git. انتبه لهذا قبل ما تشغّله على
قروب فيه نقاشات حساسة.

**الدقة تحتاج ضبطًا.** أول يومين راح تطلع مهام زائدة أو ناقصة. عدّل:
- `MY_NAMES` — أضف كل صيغة ينادونك بها فعليًا (هذا أكبر مصدر للتحسين).
- `MIN_CONFIDENCE` — ارفعه لتقليل الضجيج، أنزله لو فاتته مهام.
- في الوضع الذكي: قسم "ما لا يُعتبر مهمة" في `src/classify.js`.
- في وضع القواعد: `RULE_KEYWORDS` في `.env`، أو قوائم الإشارات في `src/rules.js`.

المهام اللي ثقتها أقل من 75٪ تظهر في اللوحة بوسم "راجعها".

**الخطوط.** اللوحة تستخدم عائلة ثمانية بوجهين، كلٌّ في موضعه المصمَّم له:
**Serif Display** للترويسة وعناوين المهام، و**Serif Text** لنص الواجهة والشرائح
والأزرار. كل وجه بخمسة أوزان، وSans يبقى احتياطيًا في سلسلة الخطوط.

ملفات الخط **غير مرفوعة** للمستودع لأن ترخيص إعادة التوزيع يخص ثمانية — انسخها
محليًا إلى `public/fonts/`:

```
thmanyahserifdisplay-{Light,Regular,Medium,Bold,Black}.woff2
thmanyahseriftext-{Light,Regular,Medium,Bold,Black}.woff2
thmanyahsans-{Light,Regular,Medium,Bold,Black}.woff2
```

بدونها تشتغل اللوحة بخط النظام تلقائيًا دون أي خطأ.

**الثيم.** زر في أعلى اللوحة يبدّل بين: تلقائي (حسب النظام) ← فاتح ← داكن،
والاختيار محفوظ في المتصفح.

**المهام الدورية.** جدول أسبوعي ثابت لتحضير المواد. انسخ
`recurring.example.json` إلى `recurring.json` وعدّل المواد وأيامها
(`0`=الأحد … `6`=السبت). تُنشأ المهمة قبل يوم المحاضرة بيوم (`leadDays`)
وموعدها يوم المحاضرة، وتظهر في سكشن «مهام دورية» أعلى اللوحة منفصلةً عن
الوارد من القروب.

المادة الواحدة تتكرر أسبوعيًا بنفس العنوان، فمنعُ التكرار فيها بالعنوان
**والتاريخ** معًا لا بالعنوان وحده — وإلا حجب المنعُ العام محاضرتَي الثلاثاء
والخميس. ولهذا أيضًا لا يوقف حذفُ مهمة تكرارَ المادة.

تعديل `recurring.json` يسري خلال ساعة **بلا إعادة تشغيل** — الجدول يُقرأ في كل
دورة لا مرة واحدة عند الإقلاع، ولو فسد الملف يبقى آخر جدول صالح عاملًا.

> تغيير يوم مادة لا يحذف مهامها المولّدة سابقًا لليوم القديم — احذفها من اللوحة.

`recurring.json` مستثنى من Git لأنه جدولك الشخصي.

**التعديل والحذف.** زر «✎ تعديل» يفتح نموذجًا داخل البطاقة لتغيير العنوان
والتفاصيل والموعد والأولوية (`Esc` للإلغاء). والحذف **نهائي**: يزيل صف المهمة،
ويترك شاهدًا بعنوانها المطبّع فقط حتى لا تعود عند `npm run reprocess`. المهمة
المنجزة كذلك لا تعود مفتوحة.

> الرسالة الأصلية تبقى في جدول `messages` بعد حذف المهمة — الحذف يخص المهمة
> لا الرسالة. لمحو كل شيء احذف `data/tasks.db`.

**المهام اليدوية.** زر «+» الدائري يضيف مهمة لم تأتِ من القروب — تظهر بوسم
«✎ يدوية» وتُعامل مثل بقية المهام. الإضافة اليدوية تتخطى فحص التكرار، لأن التكرار
فيها قرارك أنت. اختصار: `Cmd/Ctrl+Enter` للإرسال، و`Esc` للإغلاق.

## التكلفة

**وضع القواعد: صفر.** ما يتصل بأي خدمة مدفوعة إطلاقًا.

أما الوضع الذكي: الدفعة الواحدة (25 رسالة تقريبًا) تستهلك ~1500 توكن دخل و~200 خرج.
التعليمات الثابتة مخزّنة في الكاش فتُحسب بربع السعر بعد أول استدعاء.

قروب متوسط الحركة (300 رسالة يوميًا) ≈ 12 دفعة، وهو استهلاك يومي بسيط.
لو القروب كثير الحركة، `CLAUDE_MODEL=claude-sonnet-5` يقلل التكلفة للنصف تقريبًا.

## البنية

| الملف | الدور |
|---|---|
| `src/wa.js` | اتصال واتساب، استخراج نص الرسائل، إعادة الاتصال |
| `src/pipeline.js` | تجميع الدفعات، حفظ المهام، التنبيهات والملخص |
| `src/classify.js` | تعليمات Claude ومخطط الإخراج المنظّم (الوضع الذكي) |
| `src/rules.js` | استخراج بالقواعد والمواعيد العربية (وضع القواعد) |
| `src/db.js` | SQLite ومنع تكرار المهام |
| `src/server.js` | واجهة REST للوحة |
| `public/` | اللوحة |
| `src/guard.js` | حارس يمنع الإرسال لأي قروب أو شخص |
| `src/quiet.js` | يمنع طباعة مفاتيح التشفير في السجل |
| `src/lock.js` | قفل يمنع تشغيل نسختين معًا |
| `src/freshness.js` | ينبّه إذا تغيّرت الشيفرة والبوت يعمل |
| `src/recurring.js` | توليد مهام التحضير من الجدول الأسبوعي |
